MCP Server 是通过标准协议接口，向 AI 应用提供特定能力的程序。

常见例子包括：用于访问文档的文件系统服务器、用于查询数据的数据库服务器、用于管理代码的 GitHub 服务器、用于团队沟通的 Slack 服务器，以及用于安排日程的日历服务器。

## 服务器的核心功能

服务器通过三种基本构件提供功能：

| 功能 | 说明 | 示例 | 控制方 |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------- |
| **工具** | LLM 可以主动调用的函数；模型根据用户请求决定何时使用。工具可以写入数据库、调用外部 API、修改文件或触发其他逻辑。 | 搜索航班<br />发送消息<br />创建日历事件 | 模型 |
| **资源** | 被动的数据源，提供只读的信息访问，用于补充上下文，例如文件内容、数据库 Schema 或 API 文档。 | 获取文档<br />访问知识库<br />读取日历 | 应用 |
| **提示模板** | 预先构建的指令模板，指导模型使用特定的工具和资源。 | 规划假期<br />总结会议<br />起草邮件 | 用户 |

下面通过一个假设场景，展示这些功能各自的作用，以及它们如何配合使用。

### 工具

工具让 AI 模型能够执行操作。每个工具定义一项具体操作，并为输入和输出指定类型。模型根据上下文请求执行工具。

#### 工具如何工作

工具是由 Schema 定义、可供 LLM 调用的接口。MCP 使用 JSON Schema 进行校验。每个工具执行一项操作，其输入和输出都有清晰定义。工具在执行前可能需要用户同意，帮助用户保持对模型所执行操作的控制。

**协议操作：**

| 方法 | 用途 | 返回值 |
| ------------ | ------------------------ | -------------------------------------- |
| `tools/list` | 发现可用工具 | 包含 Schema 的工具定义数组 |
| `tools/call` | 执行指定工具 | 工具执行结果 |

**工具定义示例：**

```typescript
{
  name: "searchFlights",
  description: "Search for available flights",
  inputSchema: {
    type: "object",
    properties: {
      origin: { type: "string", description: "Departure city" },
      destination: { type: "string", description: "Arrival city" },
      date: { type: "string", format: "date", description: "Travel date" }
    },
    required: ["origin", "destination", "date"]
  }
}
```

#### 示例：预订旅行

工具让 AI 应用能够代表用户执行操作。在旅行规划场景中，AI 应用可以使用多个工具，帮助用户预订假期行程：

**搜索航班**

```
searchFlights(origin: "NYC", destination: "Barcelona", date: "2024-06-15")
```

查询多家航空公司，返回结构化的航班选项。

**预留日历时间**

```
createCalendarEvent(title: "Barcelona Trip", startDate: "2024-06-15", endDate: "2024-06-22")
```

在用户日历中标记出行日期。

**邮件通知**

```
sendEmail(to: "team@work.com", subject: "Out of Office", body: "...")
```

自动向同事发送离岗通知邮件。

#### 用户交互模型

工具由模型控制，也就是说，AI 模型可以自动发现并调用工具。不过，MCP 通过多种机制强调人工监督。

为了建立信任并保障安全，应用可以通过以下方式提供用户控制：

- 在界面中展示可用工具，让用户决定某个工具是否应当在特定交互中可用
- 为单次工具执行显示批准对话框
- 通过权限设置，预先批准某些安全操作
- 使用活动日志，展示所有工具执行及其结果

### 资源

资源提供结构化的信息访问方式。AI 应用可以获取这些信息，并将其作为上下文提供给模型。

#### 资源如何工作

资源将文件、API、数据库或其他来源的数据提供给 AI，帮助它理解上下文。应用可以直接访问这些信息，并自行决定使用方式：选取相关部分、通过嵌入向量搜索，或全部传递给模型。

每个资源都有唯一 URI，例如 `file:///path/to/document.md`，并声明其 MIME 类型，以便正确处理内容。

资源支持两种发现模式：

- **直接资源** — 使用固定 URI 指向特定数据。例如：`calendar://events/2024`，返回 2024 年日历中的空闲情况
- **资源模板** — 使用带参数的动态 URI，支持灵活查询。例如：
  - `travel://activities/{city}/{category}`，按城市和类别返回活动
  - `travel://activities/barcelona/museums`，返回巴塞罗那的所有博物馆

资源模板包含标题、描述和预期 MIME 类型等元数据，因此既容易发现，也能自我说明。

**协议操作：**

| 方法 | 用途 | 返回值 |
| -------------------------- | ------------------------------- | -------------------------------------- |
| `resources/list` | 列出可用的直接资源 | 资源描述符数组 |
| `resources/templates/list` | 发现资源模板 | 资源模板定义数组 |
| `resources/read` | 获取资源内容 | 带元数据的资源数据 |
| `subscriptions/listen` | 监测资源变更 | 更新通知流 |

要监测特定资源的变更，客户端发送 [`subscriptions/listen`](/specification/2026-07-28/basic/patterns/subscriptions) 请求，在 `resourceSubscriptions` 过滤条件中列出相应资源的 URI。被监测资源发生变化时，服务器就通过所建立的流发送 `notifications/resources/updated`。

#### 示例：获取旅行规划上下文

继续使用旅行规划的例子，资源让 AI 应用能够访问相关信息：

- **日历数据**（`calendar://events/2024`）— 检查用户何时有空
- **旅行证件**（`file:///Documents/Travel/passport.pdf`）— 访问重要文件
- **历史行程**（`trips://history/barcelona-2023`）— 参考过去的旅行和偏好

AI 应用获取这些资源后，自行决定如何处理：通过嵌入向量或关键词搜索选取部分数据，或将原始数据直接交给模型。

在本例中，应用将日历数据、天气信息和旅行偏好提供给模型，使其能够检查空闲时间、了解天气规律，并参考过去的旅行偏好。

**资源模板示例：**

```json
{
  "uriTemplate": "weather://forecast/{city}/{date}",
  "name": "weather-forecast",
  "title": "Weather Forecast",
  "description": "Get weather forecast for any city and date",
  "mimeType": "application/json"
}

{
  "uriTemplate": "travel://flights/{origin}/{destination}",
  "name": "flight-search",
  "title": "Flight Search",
  "description": "Search available flights between cities",
  "mimeType": "application/json"
}
```

这些模板支持灵活查询。对于天气数据，用户可以查询任意城市与日期组合的预报；对于航班，用户可以搜索任意两个机场之间的路线。当用户在 `origin` 机场中输入 "NYC"，并开始在 `destination` 机场中输入 "Bar" 时，系统可以建议 "Barcelona (BCN)" 或 "Barbados (BGI)"。

#### 参数补全

动态资源支持参数补全。例如：

- 为 `weather://forecast/{city}` 输入 "Par" 时，可能建议 "Paris" 或 "Park City"
- 为 `flights://search/{airport}` 输入 "JFK" 时，可能建议 "JFK - John F. Kennedy International"

系统帮助用户发现有效值，无需用户事先掌握精确格式。

#### 用户交互模型

资源由应用驱动，因此应用可以灵活决定如何获取、处理和展示可用上下文。常见交互模式包括：

- 通过树形或列表视图，以熟悉的文件夹式结构浏览资源
- 通过搜索和筛选界面查找特定资源
- 根据启发式规则或 AI 选择，自动加入上下文或提供智能建议
- 通过手动或批量选择界面，加入一个或多个资源

应用可以使用任何符合自身需求的界面模式来实现资源发现。协议不强制采用某种 UI 模式，因此可以实现带预览的资源选择器、基于当前对话上下文的智能建议、一次加入多个资源的批量选择，或与现有文件浏览器和数据探索工具集成。

### 提示模板

提示模板可复用，使 MCP Server 的开发者能够针对特定领域提供参数化提示，或展示如何更好地使用 MCP Server。

#### 提示模板如何工作

提示模板是结构化的模板，定义预期输入和交互模式。它们由用户控制，需要显式调用，而不会自动触发。提示模板可以感知上下文，引用可用资源和工具，形成完整的工作流。与资源类似，提示模板也支持参数补全，帮助用户发现有效的参数值。

**协议操作：**

| 方法 | 用途 | 返回值 |
| -------------- | -------------------------- | ------------------------------------- |
| `prompts/list` | 发现可用提示模板 | 提示模板描述符数组 |
| `prompts/get` | 获取提示模板详情 | 包含参数的完整提示模板定义 |

#### 示例：简化工作流

提示模板为常见任务提供结构化模板。在旅行规划场景中：

**“规划假期”提示模板：**

```json
{
  "name": "plan-vacation",
  "title": "Plan a vacation",
  "description": "Guide through vacation planning process",
  "arguments": [
    { "name": "destination", "type": "string", "required": true },
    { "name": "duration", "type": "number", "description": "days" },
    { "name": "budget", "type": "number", "required": false },
    { "name": "interests", "type": "array", "items": { "type": "string" } }
  ]
}
```

相比非结构化的自然语言输入，提示模板系统支持：

1. 选择“规划假期”模板
2. 结构化输入：巴塞罗那、7 天、3000 美元、["海滩", "建筑", "美食"]
3. 根据模板，一致地执行工作流

#### 用户交互模型

提示模板由用户控制，需要显式调用。协议允许实现者自由设计符合应用习惯的界面，主要原则包括：

- 易于发现可用提示模板
- 清晰说明每个提示模板的用途
- 自然地输入参数，并进行校验
- 透明展示提示模板的底层模板内容

应用通常通过以下 UI 模式提供提示模板：

- 斜杠命令：输入 "/"，查看 /plan-vacation 等可用提示模板
- 命令面板：通过搜索访问提示模板
- 专用 UI 按钮：用于经常使用的提示模板
- 上下文菜单：建议与当前场景相关的提示模板

## 让多个服务器协同工作

多个服务器通过统一接口组合各自的专长时，MCP 的真正价值便会显现。

### 示例：多个服务器协同规划旅行

设想一个个性化 AI 旅行规划应用，连接了三个服务器：

- **旅行服务器** — 处理航班、酒店和行程
- **天气服务器** — 提供气候数据和天气预报
- **日历／邮件服务器** — 管理日程和通信

#### 完整流程

1. **用户调用提示模板并提供参数：**

   ```json
   {
     "prompt": "plan-vacation",
     "arguments": {
       "destination": "Barcelona",
       "departure_date": "2024-06-15",
       "return_date": "2024-06-22",
       "budget": 3000,
       "travelers": 2
     }
   }
   ```

2. **用户选择要加入的资源：**
   - `calendar://my-calendar/June-2024`（来自日历服务器）
   - `travel://preferences/europe`（来自旅行服务器）
   - `travel://past-trips/Spain-2023`（来自旅行服务器）

3. **AI 使用工具处理请求：**

   AI 首先读取所有选定资源，收集上下文：从日历中识别空闲日期，从旅行偏好中了解喜欢的航空公司和酒店类型，并从历史行程中了解过去喜欢的地点。

   随后，AI 利用这些上下文执行 AI 应用提供的提示模板。本例中，AI 应用将已连接 MCP 天气服务器的天气工具提供给模型。由于天气会影响旅行计划，AI 在理解提示模板时选择调用 `checkWeather()`。

   因此，AI 会依次执行一系列工具：

   - `searchFlights()` — 查询航空公司，搜索纽约市飞往巴塞罗那的航班
   - `checkWeather()` — 获取旅行日期的天气预报

   接着，AI 根据这些信息完成预订及后续步骤，并在需要时请求用户批准：
   - `bookHotel()` — 查找符合指定预算的酒店
   - `createCalendarEvent()` — 将旅行加入用户日历
   - `sendEmail()` — 发送包含旅行详情的确认邮件

**最终结果：** 用户通过多个 MCP Server，查询并预订了符合自身日程的巴塞罗那之旅。“规划假期”提示模板引导 AI 跨服务器组合资源（日历空闲时间和旅行历史）与工具（搜索航班、预订酒店、更新日历），完成上下文收集和预订执行。原本可能耗费数小时的任务，借助 MCP 几分钟即可完成。
