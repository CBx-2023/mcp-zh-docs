Inspector 是一款会持有真实凭据、启动真实进程的开发工具。本页集中说明它提供哪些保护、信任哪些主体，以及各项边界在哪里，帮助你选择适合自己机器的配置。配置页与实践指南会链接到这里，不再重复背后的原因。

主要要点如下：

- **Web 后端能够启动进程。** API Token 是将这项能力与其他能够访问该端口的主体隔开的保护。
- **存在操作系统钥匙串时，密钥会保存在其中。** 否则会自动回退到文件；该文件**只有在你提供密钥时才会加密，否则是明文**。
- **stdio 服务器以你的身份运行。** Inspector 能读取的内容，由它启动的服务器通常也能读取。
- **mcpdo 守护进程是持有活动连接的长驻进程**，由 Token 和仅限同一用户的文件权限保护。

## Web 后端及其 API Token

Web 客户端是在浏览器中运行的应用，其后端 Node 服务器持有 MCP 连接。这个服务器可以按请求启动 stdio 进程，因此每条 `/api/*` 路由都要求提供每次启动独立生成的 Bearer Token（`x-mcp-remote-auth: Bearer <token>`）。浏览器如何取得它，见[会话 Token](/docs/2026-07-28/tools/inspector/web#the-session-token)。

Token 能保护什么、不能保护什么：

- **对于非浏览器客户端，Token 才是真正的保护。** 来源允许列表（`ALLOWED_ORIGINS`）会阻止其他网页驱动后端，但**没有** `Origin` 请求头的请求，例如 curl、脚本或任何非浏览器客户端，会完全跳过这项检查。
- **`GET /` 会披露 Token。** 后端将 Token 注入提供的 HTML，让重新加载和书签仍能正常工作。因此，任何能够加载页面的人都可以读取 Token，这就是绑定地址比 Token 值本身更重要的原因。自行固定 `MCP_INSPECTOR_API_TOKEN` 不会改变这一点，因为自定义 Token 与生成的 Token 一样会被披露。
- **`DANGEROUSLY_OMIT_AUTH=true` 会彻底移除这道保护。** 之后，任何能访问端口的主体都可以以你的身份启动进程，并使用 Inspector 持有的任意 OAuth Token。只有 `true` 或 `1` 会关闭身份验证；其他值，包括 `false`，都会保持开启。
- **只有 `/api/*` 受保护。** 页面本身、静态资源和 `GET /healthz` 无需 Token 即可访问。`/healthz` 只返回 `{"status":"ok"}`，供容器和编排器探测。

### 后端监听在哪里

后端默认绑定 `127.0.0.1`。除非设置 `DANGEROUSLY_BIND_ALL_INTERFACES=true`，否则会拒绝绑定所有接口，包括 `0.0.0.0`、`::` 及等价写法。绑定某个特定地址无需额外启用，因为这只是一次明确选择的暴露，而不是同时暴露全部接口。见[在网络上提供访问](/docs/2026-07-28/tools/inspector/recipes#hosting-on-a-network)。

<Warning>
  绝对不要将 `DANGEROUSLY_OMIT_AUTH` 与非回环绑定一起使用。如果需要让其他人访问 Inspector，请在它前面设置真正的访问控制边界：进行身份验证的反向代理、SSH 隧道，或私有网络。
</Warning>

## Docker

[Docker 镜像](/docs/2026-07-28/tools/inspector/recipes#docker) 会改变上述情况中的两点。

### 仅在回环地址发布端口

Inspector 在容器中必须绑定 `0.0.0.0`，才能通过 `-p` 访问，因此镜像设置了 `DANGEROUSLY_BIND_ALL_INTERFACES=true`。这一选项控制的是**容器的**网络接口，而不是主机。哪些主机接口可以访问 Inspector，取决于端口的发布方式：

| 发布参数 | 可从哪里访问 |
| ------------------------ | ------------------------------------------------ |
| `-p 127.0.0.1:6274:6274` | 仅限本机。 |
| `-p 6274:6274`（不带地址前缀） | **主机的所有网络接口**，也就是整个网络。 |

不带地址的 `-p` 会将能够启动进程的后端，以及披露其 Token 的页面暴露到局域网。每个发布的端口都要保留 `127.0.0.1:` 前缀，包括 `6274`，以及在发布 MCP Apps 监听器时使用的 `6275` / `6278`。

### 数据卷会将密钥写入磁盘

容器没有操作系统钥匙串。如果没有在 `/home/node/.mcp-inspector` 挂载卷，密钥会在会话期间留在**内存中**，并在容器退出时丢失。为了保留服务器列表而挂载该卷，也会让密钥改为存入卷上的 `secrets.json` 文件；该文件**只有在你提供密钥时才会加密，否则是明文**。root、主机 `docker` 组的每位成员（该权限等同于 root），以及任何拿到卷备份、快照或副本的人，都可以读取它。

请通过 `MCP_INSPECTOR_SECRET_KEY_FILE` 将密钥作为文件提供，例如 Docker 或 Compose secret，而不是通过环境变量：使用 `-e MCP_INSPECTOR_SECRET_KEY=…` 传入的密钥，任何可以运行 `docker inspect` 或 `docker exec` 的人都能看到。实践指南展示了两种形式。

## 密钥存储

Inspector 不会把凭据保存在 `mcp.json`、`client.json` 和 `oauth.json` 中，以免在分享、提交或同步这些文件时泄露。以下内容会作为密钥存储：

- 获得的 OAuth Token，包括访问 Token、刷新 Token 和 ID Token，受 [`MCP_INSPECTOR_PERSIST_TOKENS`](/docs/2026-07-28/tools/inspector/configuration#secret-store-variables) 控制；以及企业管理授权中的 IdP 会话 Token；
- 每个服务器的 OAuth 客户端密钥，以及企业 IdP 客户端密钥；
- 动态注册的客户端密钥及其注册访问 Token；
- 每个 stdio 服务器的 `env:` 值。

**`headers` 不被视为密钥。** 它们会完全按原样保存在 `mcp.json` 中，因此携带凭据的请求头，例如 API Key 或静态 `Authorization` 值，仍会留在文件里。

如何选择和更改存储方式，见[密钥存储位置](/docs/2026-07-28/tools/inspector/configuration#where-secrets-are-stored)。本节主要讨论风险。

### 自动回退到明文

<Warning>
在无法访问操作系统钥匙串的主机上，例如没有 libsecret 或未运行 Secret Service 的 Linux、没有 D-Bus 会话的无头服务器或 SSH 会话，以及 Android/Termux，Inspector 会**自动**把密钥保存在 `~/.mcp-inspector/secrets.json` 中。无需你另行启用；除非提供密钥，否则该文件**未经加密**。

唯一的提示是选择存储方式时 stderr 中的一条警告，以及 Web 客户端设置对话框中的页脚。

</Warning>

应当把这看作风险，而不仅是一项配置事实。文件以 `0600` 权限写入，只能阻止其他非 root 用户访问，除此以外没有保护。要消除这一风险，可以选择以下方案之一：

- 恢复钥匙串：安装 libsecret 并运行 Secret Service，例如 `gnome-keyring`，或在桌面会话中运行；
- 通过 `MCP_INSPECTOR_SECRET_KEY_FILE` 中生成的密钥加密文件；
- 或设置 `MCP_INSPECTOR_SECRET_STORE=memory`，并在每次会话重新输入密钥。

### 文件存储能防范什么

文件存储为没有钥匙串的机器提供支持，但其保护较弱。即使**已经加密**，将密钥保存在其中仍应视为中等风险。

**没有密钥时（明文，权限 `0600`）：**

| 威胁 | 能防范？ |
| --------------------------------------------------------------------------------------- | ---------- |
| 文件权限保持有效时，机器上的其他非 root 用户 | 是 |
| root，以及容器主机上 `docker` 组的每位成员 | 否 |
| 任何持有文件副本的人，包括备份、快照、同步的主目录或提交记录 | 否 |
| 以你的用户身份运行的任何程序，包括 Inspector 启动的 stdio 服务器 | 否 |

**提供密钥时（AES-256-GCM，每次写入使用随机盐，通过 scrypt 派生密钥）：**

| 威胁 | 能防范？ |
| ---------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 文件本身泄露，例如备份、快照、副本或提交记录，前提是密钥具有高熵，且未随文件一起泄露 | 是 |
| 能够从保存位置读取密钥的任何人 | 否 |
| 主机上的 root 或 `docker` 组：他们可以读取文件、密钥，或持有解密值的进程内存 | 否 |
| 以同一用户身份运行的代码 | 否 |
| 弱口令：任何持有文件的人都能快速离线猜测，因为每次保存都需要派生，所以 scrypt 成本设置较低 | 否 |

第二行的保护边界取决于密钥保存在哪里。使用 `MCP_INSPECTOR_SECRET_KEY` 时，密钥位于 Inspector 的环境中，同一用户或 root 可以通过 `/proc/<pid>/environ` 读取；容器中可以通过 `docker inspect` / `docker exec` 读取；你为启动程序保存它的位置，例如 Shell 配置文件、`.env` 文件或 Compose 文件，也可能包含它。`MCP_INSPECTOR_SECRET_KEY_FILE` 将范围缩小到能够读取密钥文件的主体，但 Inspector 必须能读取它，因此同一用户也可以。如果密钥与密钥存储文件并排保存，或位于同一备份、卷或仓库中，加密就没有带来额外保护。

简言之，加密将“文件泄露”变成“文件**和**密钥都泄露”。对于已经拥有主机或容器中 root 权限，或 Inspector 自身用户权限的人，它没有帮助。如果不能接受这一点，请使用钥匙串或内存存储。

以下两类失败会明确报错，而不是静默处理：

- 密钥文件不存在、不可读或为空，`MCP_INSPECTOR_SECRET_KEY_FILE` 被设置为空值，或同时设置了两个密钥变量时，存储会**拒绝读写**，而不是回退到明文。
- 口令更改或丢失时，现有文件将无法解密。Inspector 将其视为空，并**拒绝覆盖它**，因此需要恢复口令，或删除文件并重新输入各项值。

## stdio 服务器以你的身份运行

stdio MCP Server 是 Inspector 以你的用户权限启动的进程，与任何 MCP Host 的做法相同。

- **环境：** Inspector 不会直接传递自身环境。stdio 服务器只会收到简短的允许列表，在 macOS 和 Linux 上包括 `HOME`、`LOGNAME`、`PATH`、`SHELL`、`TERM`、`USER`，再加上其配置的 `env:`。因此，`MCP_INSPECTOR_SECRET_KEY` 中的密钥不会被直接交给它。
- **但它仍是同一个用户。** 服务器可以自行打开 `secrets.json`，读取 `oauth.json` 和你的 Catalog，通常也能通过 `/proc/<pid>/environ` 读取 Inspector 的环境。环境允许列表只是良好卫生措施，不是隔离机制。

只连接你愿意信任其接触这些密钥的 stdio 服务器。对于不信任的服务器，可用容器包装其命令，例如将 `docker run -i --rm --network none <image>` 作为 stdio 命令。HTTP 和 SSE 服务器不运行本地代码，因此不需要进程隔离。

## mcpdo 连接守护进程

[mcpdo](/docs/2026-07-28/tools/inspector/mcpdo) 将连接交给后台守护进程 `mcpdod`，从而在命令之间保持连接。第一次有命令需要它时，例如 `mcpdo connect` 或针对某条连接的任意命令，它会**自动**启动，没有独立的“启动守护进程”步骤需要主动启用。本节介绍该进程暴露的能力。

### 客户端如何访问它，还有谁能访问

| 平台 | 端点 |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS / Linux | 守护进程目录中的 Unix socket，即 `mcpdod.sock`；目录默认为 `~/.mcp-inspector`。 |
| Windows | 根据守护进程目录派生的命名管道 `\\.\pipe\mcp-conn-<hash>`。它周围没有目录权限保护，因此 Token 才是保护机制。 |

它**没有 TCP 端口**，所以机器外的主体无法访问。Unix 上，守护进程目录会被创建，或在已经存在时收紧为 `0700` 权限，归你所有，而且必须是真实目录，不能是符号链接。其中的 socket 和锁文件权限为 `0600`。因此，其他非 root 用户无法访问 socket；root 和以你身份运行的任何进程则可以。

目录按以下顺序选择：`MCP_INSPECTOR_DAEMON_DIR`，然后是 `MCP_STORAGE_DIR`，最后是 `~/.mcp-inspector`。socket 路径超过平台限制时，macOS 约为 104 字节、Linux 约为 108 字节，会在开始前拒绝，并在错误中指出应缩短哪个变量。

### 如何验证命令身份

每个请求都必须携带 Bearer Token，没有无需身份验证的请求路径。

- **共享模式（默认）：** 启动守护进程的 `mcpdo` 命令生成随机的 256 位 Token，通过环境变量交给守护进程。守护进程将它写入自身目录中的 `mcpdod.token`，权限为 `0600`，使同一用户运行的任何 `mcpdo` 命令都可以读取。该文件的文件系统权限就是信任边界，与 socket 同样采用“同一用户”的边界。
- **私有模式：** `eval "$(mcpdo private)"` 在 `$TMPDIR/mcp-conn-<uid>/` 下创建新的 `0700` 目录，并向该 Shell 导出 `MCP_INSPECTOR_DAEMON_DIR` 和 `MCP_INSPECTOR_DAEMON_TOKEN`，从而让 Shell 拥有自己的守护进程和连接。由于 `$TMPDIR` 可能共享，使用前会检查父目录 `mcp-conn-<uid>` 的所有者和符号链接情况。

Token 使用恒定时间比较。超过 1 MiB 的请求行会被拒绝。向活动守护进程提供错误 Token 的命令会明确失败，绝不会替换该守护进程。

<Note>
  私有模式隔离不同 Shell 的连接和守护进程状态，但它**不是**防范其他同用户进程的安全边界：任何与你 UID 相同、并获知守护进程目录的程序，都可以读取其 Token。需要强边界时，请使用独立用户账号或容器。
</Note>

### 内存中保存什么

只要仍在运行，守护进程就会为每条打开的连接保留：

- 活动的 MCP 连接；对于 stdio 服务器，还包括以守护进程为父进程启动的子进程；
- 连接解析后的配置，包括从密钥存储中获取的 stdio `env:` 值；
- HTTP 连接正在使用的 OAuth Token；重新连接断开的传输时，也会从存储中重新读取；
- 非交互命令留下的待处理信息征询，直到获得回答，或在 10 分钟后过期。

守护进程使用启动它的 `mcpdo` 命令的环境启动。它继承该 Shell 的变量，包括在那里设置的 `MCP_INSPECTOR_SECRET_KEY`，以及 `MCP_INSPECTOR_DAEMON_TOKEN` 中自身的 IPC Token，并在整个生命周期内保留，即使之后你修改了 Shell 中的值。它启动的 stdio 服务器仍只会收到前述允许列表和自身的 `env:`，这些内容取自运行 `mcpdo connect` 的 Shell 快照。

在没有钥匙串的主机上，mcpdo 绝不会自动回退到内存存储。它的前端命令与守护进程属于不同进程，进程私有的存储无法将 Token 从一方传给另一方。因此，mcpdo 改用**共享的 `secrets.json` 文件**，同样存在前述“未提供密钥即为明文”的问题。显式设置 `MCP_INSPECTOR_SECRET_STORE=memory` 仍会优先采用。mcpdo 每次 `connect` 只打印一次存储警告，而非每个命令都打印。

### 生命周期

- **启动：** 第一个需要它的命令触发启动。如果两个同时启动，`O_EXCL` 锁（`mcpdod.lock`）只允许一个成功。已终止守护进程留下的锁会被回收，活动守护进程绝不会被接管。
- **停止：** 使用 `mcpdo daemon stop`，或发送 `SIGINT` / `SIGTERM`。它还会在**最后一条连接关闭约 60 秒后**自行退出。没有最长运行时间：只要仍有连接打开，守护进程就会继续运行。
- **正常停止时：** 拒绝新工作，为执行中的请求提供短暂宽限期，关闭全部连接，然后移除 socket、Token 文件和锁。
- **崩溃时：** 持有的所有连接都会丢失，stdio 服务器失去 stdin，通常也会退出。已存储的 OAuth Token 和密钥不受影响。下一个 `mcpdo` 命令会启动新的守护进程，清理过期 socket、回收锁并写入新 Token。连接需要通过 `mcpdo connect` 重新建立。

使用 `pgrep mcpdod` 查找遗留的守护进程。它会将进程标题设为 `mcpdod`。

### 写入磁盘的内容

所有文件都位于权限为 `0700` 的守护进程目录中：

| 文件 | 权限 | 内容 |
| -------------- | ------ | ------------------------------------------------------------------------------------------------------ |
| `mcpdod.sock` | `0600` | IPC socket，仅限 Unix。 |
| `mcpdod.lock` | `0600` | 单实例锁，保存守护进程 PID。 |
| `mcpdod.token` | `0600` | IPC Bearer Token，在启动时写入，正常关闭时移除。 |
| `mcpdod.log` | `0600` | 守护进程的 stderr，每次启动重新创建。启动失败和密钥存储警告会写入这里。 |

守护进程与其他客户端使用同一份 `oauth.json` 和密钥存储写入 OAuth 状态及密钥，因此[密钥存储](#secret-storage)中的所有说明也同样适用。
