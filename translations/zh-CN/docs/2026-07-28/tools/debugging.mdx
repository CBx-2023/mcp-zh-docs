开发 MCP Server 或将其集成到应用时，有效调试至关重要。本指南介绍 MCP 生态中可用的调试工具与方法。

## 调试工具概览

MCP 提供多种工具，用于不同层次的调试：

1. **[MCP Inspector](/docs/2026-07-28/tools/inspector)**：交互式、与传输方式无关的测试 UI。连接 stdio 或 Streamable HTTP 服务器，调用[工具](/specification/latest/server/tools)、[提示模板](/specification/latest/server/prompts)和[资源](/specification/latest/server/resources)，并查看通知流。它应当是你的首选调试入口。
2. **服务器日志**：通过 stderr（stdio 传输）或 [OpenTelemetry](https://opentelemetry.io/)（所有传输方式）记录结构化日志。自协议版本 `2026-07-28` 起，通过协议传递的[日志](/specification/2026-07-28/server/utilities/logging)（`notifications/message`）已被弃用。
3. **客户端开发工具**：多数 MCP Client 会提供日志和连接状态。下文的[在 Claude Desktop 中调试](#debugging-in-claude-desktop)是一个示例，也可以查阅所用客户端的文档。

## 实现日志

### 服务器端日志

构建使用本地 [stdio 传输](/specification/2026-07-28/basic/transports/stdio)的服务器时，宿主应用会自动捕获所有写入 stderr（标准错误）的日志消息。

<Warning>

本地 MCP Server 不应将日志写入 stdout（标准输出），否则会干扰协议运行。

</Warning>

对于使用 [Streamable HTTP 传输](/specification/2026-07-28/basic/transports/streamable-http)的服务器，客户端不会捕获 stderr。请使用自己的服务器端日志聚合方案或 [OpenTelemetry](https://opentelemetry.io/) 收集日志，并使用标准 HTTP 工具，例如 curl、浏览器开发者工具的 Network 面板，检查请求与 SSE 流。

<Warning>

以下 `notifications/message` 机制自协议版本 `2026-07-28` 起已被弃用。在弃用过渡期内，它仍然可用。

</Warning>

无论使用哪种[传输方式](/specification/latest/basic/transports)，都应记录服务器运行时正在做什么：

<CodeGroup>

```python Python
import logging

from mcp.server import MCPServer

logger = logging.getLogger(__name__)

mcp = MCPServer("reports")


@mcp.tool()
async def fetch_report(report_id: str) -> str:
    """Fetch a report by id."""
    logger.info("Fetching report %s", report_id)
    return f"Report {report_id} is ready."
```

```typescript TypeScript
await server.sendLoggingMessage({
  level: "info",
  data: "Server started successfully",
});
```

</CodeGroup>

MCP 定义了八个 [RFC 5424 严重性级别](/specification/latest/server/utilities/logging#log-levels)，从 `debug` 到 `emergency`。客户端通过在请求的 `_meta` 中设置 [`io.modelcontextprotocol/logLevel`](/specification/2026-07-28/server/utilities/logging#per-request-log-level) 字段，逐个请求主动启用日志消息。对于省略该字段的请求，服务器不得发送 `notifications/message`。

需要记录的重要事件：

- 启动步骤
- 资源访问
- 工具执行
- 错误情况
- 性能指标

## 常见问题

以下示例使用 Claude Desktop 的 [`claude_desktop_config.json`](/docs/2026-07-28/develop/connect-local-servers)；相同原则也适用于任何基于 stdio 的 MCP Client。

### 工作目录

MCP Client 启动 stdio 服务器时：

- 通过客户端配置启动的服务器，其工作目录可能不明确，例如 macOS 上可能为 `/`，因为客户端可能从任意位置启动
- 配置和 `.env` 文件中始终使用绝对路径，确保稳定运行
- 直接通过命令行测试服务器时，工作目录就是执行命令的位置

例如，在 `claude_desktop_config.json` 中使用：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/username/data"
      ]
    }
  }
}
```

而不是 `./data` 这样的相对路径

### 环境变量

通过 stdio 启动的 MCP Server 默认只会自动继承有限的环境变量子集，具体范围因平台而异。

要覆盖默认变量或提供自己的变量，可以在 `claude_desktop_config.json` 中指定 `env` 键：

```json
{
  "mcpServers": {
    "myserver": {
      "command": "mcp-server-myapp",
      "env": {
        "MYAPP_API_KEY": "some_key"
      }
    }
  }
}
```

### 服务器启动

常见启动问题：

1. **路径问题**
   - 服务器可执行文件路径不正确
   - 缺少必需文件
   - 权限问题
   - 尝试为 `command` 使用绝对路径

2. **配置错误**
   - JSON 语法无效
   - 缺少必填字段
   - 类型不匹配

3. **环境问题**
   - 缺少环境变量
   - 变量值不正确
   - 权限限制

### 连接问题

服务器无法连接时：

1. 检查客户端日志
2. 确认服务器进程正在运行
3. 使用 [Inspector](/docs/2026-07-28/tools/inspector) 独立测试
4. 确认[协议兼容性](/docs/2026-07-28/learn/versioning#negotiation)：调用 [`server/discover`](/specification/2026-07-28/server/discover)，查看服务器支持哪些协议版本。`UnsupportedProtocolVersionError`（`-32022`）会在其 `data` 字段中列出支持的版本
5. 检查[每个请求的 `_meta` 字段](/specification/2026-07-28/basic/index#meta)：每个请求都必须携带 `io.modelcontextprotocol/protocolVersion` 和 `io.modelcontextprotocol/clientCapabilities`，客户端也应当包含 `io.modelcontextprotocol/clientInfo`。缺少任一必填字段时，请求会以 `-32602`（Invalid params）拒绝；许多其他格式错误的输入也会返回这个错误码。如果服务器需要请求的 `clientCapabilities` 中没有声明的能力，例如[信息征询](/specification/2026-07-28/client/elicitation)，就会返回 `MissingRequiredClientCapabilityError`（`-32021`），并指出缺少哪些能力。检查请求的 `_meta` 和 [`server/discover`](/specification/2026-07-28/server/discover) 响应，确认双方声明了预期内容

## 在 Claude Desktop 中调试

Claude Desktop 是众多 MCP Client 之一，支持 macOS、Windows 和 Linux。

### 检查服务器状态

点击聊天输入框中的 "Add files, connectors, and more" 加号图标，然后将鼠标悬停在 **Connectors** 菜单上，查看已连接服务器与可用工具。

<img src="/images/available-mcp-tools.png" alt="可用的 MCP 工具" />

### 查看日志

日志文件写入以下位置：

- macOS：`~/Library/Logs/Claude`
- Windows：`%APPDATA%\Claude\logs`

<CodeGroup>

```bash macOS
tail -n 20 -F ~/Library/Logs/Claude/mcp*.log
```

```powershell Windows
type "$env:AppData\Claude\logs\mcp*.log"
```

</CodeGroup>

日志包含：

- 服务器连接事件
- 配置问题
- 运行时错误
- 消息交互

### 使用 Chrome DevTools

在 Claude Desktop 中打开 Chrome 开发者工具，排查客户端错误：

1. 创建 `developer_settings.json` 文件，将 `allowDevTools` 设为 true：

<CodeGroup>

```bash macOS
echo '{"allowDevTools": true}' > ~/Library/Application\ Support/Claude/developer_settings.json
```

```powershell Windows
'{"allowDevTools": true}' | Set-Content "$env:AppData\Claude\developer_settings.json"
```

</CodeGroup>

2. 打开 DevTools：macOS 使用 `Command-Option-I`，Windows 使用 `Ctrl+Alt+I`

注意：会出现两个 DevTools 窗口：

- 主内容窗口
- 应用标题栏窗口

使用 Console 面板检查客户端错误。

使用 Network 面板检查：

- 消息载荷
- 连接耗时

## 调试工作流

### 开发周期

1. 初始开发
   - 使用 [Inspector](/docs/2026-07-28/tools/inspector) 进行基础测试
   - 实现核心功能
   - 添加日志记录点

2. 集成测试
   - 在目标 MCP Client 中测试
   - 监控日志
   - 检查错误处理

### 测试改动

为了高效测试改动：

- **配置改动**：重启 MCP Client
- **服务器代码改动**：重启客户端；对于 Claude Desktop，需要完全退出后重新打开，仅关闭窗口不够
- **快速迭代**：开发过程中使用 [Inspector](/docs/2026-07-28/tools/inspector)

## 最佳实践

### 日志策略

1. **结构化日志**
   - 使用一致的格式
   - 包含上下文
   - 添加时间戳
   - 跟踪请求 ID

2. **错误处理**
   - 记录堆栈跟踪
   - 包含错误上下文
   - 跟踪错误模式
   - 监控恢复过程

3. **性能跟踪**
   - 记录操作耗时
   - 监控资源使用
   - 跟踪消息大小
   - 测量延迟

### 安全注意事项

调试时：

1. **敏感数据**
   - 清理日志中的敏感信息
   - 保护凭据
   - 遮蔽个人信息

2. **访问控制**
   - 验证权限
   - 检查身份验证
   - 监控访问模式

关于 MCP 攻击向量与缓解措施的完整说明，见[安全最佳实践](/docs/2026-07-28/tutorials/security/security_best_practices)。

## 获取帮助

遇到问题时：

1. **首先尝试**
   - 检查服务器日志
   - 使用 [Inspector](/docs/2026-07-28/tools/inspector) 测试
   - 复核配置
   - 验证环境

2. **支持渠道**
   - [GitHub Issues](https://github.com/modelcontextprotocol/modelcontextprotocol/issues)
   - [GitHub Discussions](https://github.com/modelcontextprotocol/modelcontextprotocol/discussions)

3. **提供的信息**
   - 日志摘录
   - 配置文件
   - 复现步骤
   - 环境详情
