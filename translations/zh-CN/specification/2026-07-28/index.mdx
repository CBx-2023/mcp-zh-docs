[Model Context Protocol](https://modelcontextprotocol.io)（MCP）是一种开放协议，让 LLM 应用能够与外部数据源和工具无缝集成。无论你是在构建 AI 驱动的 IDE、增强聊天界面，还是创建自定义 AI 工作流，MCP 都提供了一种标准化方式，将 LLM 与其所需的上下文连接起来。

本规范以 TypeScript Schema [schema.ts](https://github.com/modelcontextprotocol/specification/blob/main/schema/2026-07-28/schema.ts) 为基础，定义具有权威性的协议要求。

实现指南和示例请参阅 [modelcontextprotocol.io](https://modelcontextprotocol.io)。

本文中的关键词 "MUST"、"MUST NOT"、"REQUIRED"、"SHALL"、"SHALL NOT"、"SHOULD"、"SHOULD NOT"、"RECOMMENDED"、"NOT RECOMMENDED"、"MAY" 和 "OPTIONAL"，当且仅当以此处所示的全大写形式出现时，才按照 [BCP 14](https://datatracker.ietf.org/doc/html/bcp14) [[RFC2119](https://datatracker.ietf.org/doc/html/rfc2119)] [[RFC8174](https://datatracker.ietf.org/doc/html/rfc8174)] 中的定义解释。

## 概述

MCP 为应用提供了标准化方式，用于：

- 与语言模型共享上下文信息
- 向 AI 系统提供工具和能力
- 构建可组合的集成与工作流

协议通过 [JSON-RPC](https://www.jsonrpc.org/) 2.0 消息，在以下各方之间建立通信：

- **Host**：发起连接的 LLM 应用
- **Client**：宿主应用内部的连接组件
- **Server**：提供上下文和能力的服务

MCP 的部分设计灵感来自 [Language Server Protocol](https://microsoft.github.io/language-server-protocol/)。后者统一了在整个开发工具生态中增加编程语言支持的方式；与之类似，MCP 统一了向 AI 应用生态集成额外上下文和工具的方式。

## 关键内容

### 基础协议

- [JSON-RPC](https://www.jsonrpc.org/) 消息格式
- 无状态且自包含的请求
- 按请求进行能力协商

### 功能

服务器可以向客户端提供以下任意功能：

- **资源**：供用户或 AI 模型使用的上下文和数据
- **提示模板**：面向用户的模板化消息与工作流
- **工具**：供 AI 模型执行的函数

客户端可以向服务器提供以下功能：

- **信息征询**：由服务器发起，向用户请求额外信息

### 其他实用功能

- 配置
- 进度跟踪
- 取消
- 错误报告

### 扩展

在核心协议之外，MCP 还定义了可选的[扩展](/extensions/overview)，用于增加模块化、专用或实验性的功能。扩展始终需要主动启用，并要求客户端和服务器双方明确支持，在初始化时完成协商。主要扩展包括：

- **[任务](/extensions/tasks/overview)**：异步执行长时间运行的操作，支持轮询、执行中补充输入以及持久句柄
- **[Skills over MCP](/community/working-groups/skills-over-mcp)**：通过 MCP 发现和使用面向智能体工作流的丰富结构化指令
- **[MCP Apps](/extensions/apps/overview)**：在对话中内联渲染交互式 UI 元素，例如图表、表单和视频播放器

## 安全、信任与保障

Model Context Protocol 通过任意数据访问与代码执行路径提供强大的能力。这些能力也带来了重要的安全与信任问题，所有实现者都必须认真处理。

### 关键原则

1. **用户同意与控制**
   - 用户必须明确同意并理解所有数据访问和操作
   - 用户必须能够控制共享哪些数据，以及执行哪些操作
   - 实现者应当提供清晰的界面，便于用户审查和授权相关活动

2. **数据隐私**
   - Host 必须在向服务器提供用户数据前获得用户明确同意
   - 未经用户同意，Host 不得将资源数据传输到其他地方
   - 应当通过适当的访问控制保护用户数据

3. **工具安全**
   - 工具代表任意代码执行能力，必须谨慎对待。
     - 尤其是工具注解等行为描述，除非来自可信服务器，否则应当视为不可信信息。
   - Host 必须在调用任何工具前获得用户明确同意
   - 用户应当先理解每个工具的作用，再授权使用

### 实现指南

虽然 MCP 本身无法在协议层强制执行这些安全原则，但实现者**应当**：

1. 在应用中建立健全的用户同意和授权流程
2. 提供清晰的文档，说明安全影响
3. 实施适当的访问控制与数据保护
4. 在集成中遵循安全最佳实践
5. 在功能设计中考虑隐私影响
